## 0. 先に判断が必要なこと

### 0-1. 内部リンクのプレースホルダ（**入稿前に決める**）

本文HTMLには未公開記事へのリンクが `{{...}}` の形で5箇所残っています。

| プレースホルダ | 箇所数 | 置換先 |
|---|---|---|
| `{{URL_SIER_TENSHOKU}}` | 4 | SIer転職記事の公開URL（slug は `sier-tenshoku` で確定済み・未公開） |
| `{{URL_AGENT_CHANGE}}` | 1 | 担当者変更記事の公開URL（slug は `agent-change` で確定済み・下書き段階） |

**方針は2つあります。**

- **A案（推奨）：先に置換してから入稿する。** SIer記事・担当者変更記事の公開URLが確定してから
  本記事を入稿する。リンク切れが1本も出ません
- **B案：置換せず下書きだけ先に作る。** レビューを先に回したい場合。ただし
  **下書きのまま置換を忘れて公開すると壊れたリンクが5本出る**ため、
  入稿直後に本文を `{{` で検索し、残件を編集画面のメモに残しておくこと

どちらでも下書きである限りサイトには影響しません。レビューを急ぐならB案で構いません。

## 1. リポジトリを手元に取得

```bash
git clone https://github.com/koheiuda/nensyuagent.git
cd nensyuagent
git checkout claude/article-creation-branch-91emli
```

すでにcloneしてある場合：

```bash
cd nensyuagent
git fetch origin claude/article-creation-branch-91emli
git checkout claude/article-creation-branch-91emli
git pull
```

## 2. `.env` を作成

プロジェクトルートに `.env` を作ります。**`.gitignore` 済みなのでコミットされません。**
本リポジトリは Public のため、パスワードを他のファイルに書かないでください。

```
WP_URL=https://test-nensyu-agent.kubooo.com
WP_USER=nensyu_admin
WP_PASS=（WordPressのパスワード）
WP_BASIC_USER=check
WP_BASIC_PASS=（Basic認証のパスワード）
```

## 3. 接続確認

```bash
python3 tools/wp_draft.py --check
```

| 結果 | 意味 |
|---|---|
| `HTTP 405` | **正常。** GETを受け付けないだけで、投稿はできます |
| `HTTP 200` | 正常 |
| `HTTP 401` | Basic認証の失敗。`WP_BASIC_USER` / `WP_BASIC_PASS` を確認 |
| `HTTP 404` | XML-RPCが無効。`--mode rest` を試す（下記4-B） |

## 4. 入稿

### 4-A. 通常（XML-RPC）

**A案（プレースホルダを置換してから入稿）の場合は、先に置換します。**

```bash
# 公開URLが確定してから実行すること
sed -i '' 's|{{URL_SIER_TENSHOKU}}|https://stock-sun.com/nensyuagent/column/sier-tenshoku/|g' \
  docs/articles/大手社内SE転職_本文_20260902.html
sed -i '' 's|{{URL_AGENT_CHANGE}}|https://stock-sun.com/nensyuagent/column/agent-change/|g' \
  docs/articles/大手社内SE転職_本文_20260902.html

# 残件が0であることを確認
grep -c '{{' docs/articles/大手社内SE転職_本文_20260902.html
```

> Linux の場合は `sed -i` （`''` なし）にしてください。

**入稿コマンド（そのままコピーして実行できます）**

```bash
python3 tools/wp_draft.py \
  --html "docs/articles/大手社内SE転職_本文_20260902.html" \
  --title "大手企業の社内SEへ転職するには｜4タイプの違いと年収の見方" \
  --slug ote-shanai-se \
  --excerpt "大手企業の社内SEへの転職を検討する方へ。情報システム部門の4タイプ、求人が少ない構造的な理由と競争率、提示レンジ・賞与比率・等級で見る年収の判断軸、ベンダーコントロール経験の書き換え方、入社後のキャリアまで解説します。" \
  --category コラム \
  --status draft
```

送信内容だけ先に確認したい場合は末尾に `--dry-run` を付けてください（2026-09-02に検証済み。
本文23,900文字・ステータスdraftで正しく組み立てられることを確認しています）。

成功すると記事IDと編集URLが表示されます。

```
下書きを作成しました
  記事ID  : 123
  ステータス: draft
  編集URL : https://test-nensyu-agent.kubooo.com/wp-admin/post.php?post=123&action=edit
```

### 4-B. XML-RPCが無効な場合（REST API）

WordPress管理画面 > ユーザー > プロフィール で**アプリケーションパスワード**を発行し、
`.env` の `WP_PASS` をその値に差し替えてから、上記コマンドに `--mode rest` を足します。

※ `/wp-json/` がBasic認証の対象だとヘッダが競合します。その場合はサーバ側で
`/wp-json/` をBasic認証の除外にしてもらってください。

### 4-C. どちらも通らない場合（手貼り）

**Googleドキュメントではなく、貼付用HTMLを使ってください。**
Googleドキュメント版は変換の都合でHTMLコメント（入稿指示）とプレースホルダのリンクが
落ちています。

- **貼付用HTML（推奨）**：https://drive.google.com/file/d/119ZGtX8sixj7xZPfCgItRSlX8pp7IDKe/view
- レビュー用Googleドキュメント：https://docs.google.com/document/d/1UT26FFtS6hXD1KykgmY7KYDV81qs5KvYiSOX5K_JrOQ/edit
- リポジトリ内：`docs/articles/大手社内SE転職_本文_20260902.html`

ブロックエディタで「コードエディター」に切り替えてから貼り付けると、
表5つと見出し階層が保持されます。冒頭の【納品ヘッダー】と `<hr />` までは
納品用の情報なので**貼り付けないでください**（`docs/articles/大手社内SE転職_本文_20260902.html`
を使えばヘッダーは含まれません）。
